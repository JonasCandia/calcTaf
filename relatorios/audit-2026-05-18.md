## Veredicto de Anti-Padrões

**Não é AI slop.** O neumorfismo é implementado com coerência e não é template — as sombras variam corretamente entre claro/escuro, o `border-radius` é consistente e os tokens de shadow são aplicados de forma sistemática. JetBrains Mono para valores técnicos é uma escolha acertada. A paleta navy/gold é identidade institucional do CBMRS, não reflexo de domínio genérico.

Dois pontos a monitorar (não bloqueadores):

1. **Textura tipográfica monotona**: uppercase + tracking-widest é usado em quase todos os elementos de label — section headers, field labels, tabs, tooltips, footer. Diferenciação existe no tamanho (xs vs sm) mas o padrão é repetitivo.
2. **Badge de conceito em `text-[10px]`**: o único elemento que ficou fora da correção de tipografia. Cria inconsistência visível ao lado do score `text-6xl`.

## Achados Detalhados

### [P1] Erros de validação sem região `aria-live`

**Localização**: `src/App.tsx` — mensagens `<p>` de erro/aviso abaixo de cada `nm-inset`
**Categoria**: Acessibilidade
**Impacto**: Screen readers (NVDA, VoiceOver) não anunciam automaticamente as mensagens de erro ao serem inseridas no DOM. Usuário Sam (screen reader) clica "Calcular", os erros aparecem, mas não há anúncio sonoro — o usuário não sabe que o cálculo foi bloqueado.
**WCAG**: 4.1.3 Status Messages (AA)
**Recomendação**: Adicionar um container `aria-live="polite"` que anuncie os erros de forma consolidada:
```tsx
<div aria-live="polite" aria-atomic="true" className="sr-only">
  {Object.values(fieldErrors).join('. ')}
</div>
```
Ou adicionar `aria-describedby` em cada Input apontando para seu `<p>` de erro (com `id` correspondente).
**Comando sugerido**: `impeccable audit`

### [P1] Animação `height: auto` é layout property

**Localização**: `src/App.tsx` linha ~360 — `motion.div` do campo de natação
**Categoria**: Performance
**Impacto**: Animar `height` força layout recalculation e composite em cada frame. Em dispositivos de baixo desempenho (que são exatamente os usados em campo por militares), pode causar jank visível na revelação do campo.
**Padrão violado**: Regra de motion do impeccable — "Don't animate CSS layout properties"
**Recomendação**: Substituir pela animação de `clipPath` ou `scaleY` com `transformOrigin: top`:
```tsx
initial={{ opacity: 0, scaleY: 0 }}
animate={{ opacity: 1, scaleY: 1 }}
exit={{ opacity: 0, scaleY: 0 }}
style={{ transformOrigin: 'top' }}
```
Ou usar `max-height` com transição CSS em vez de Framer Motion para esse caso específico.
**Comando sugerido**: `impeccable animate`

### [P2] Badge de conceito com `text-[10px]` residual

**Localização**: `src/App.tsx` linha ~462 — `<div className={...text-[10px] font-black...}>`
**Categoria**: Acessibilidade / Theming
**Impacto**: Único elemento que ficou com fonte sub-12px após a correção tipográfica. Contraste especialmente crítico no badge `REGULAR` (`#F2E416` sobre fundo amarelo — razão de contraste ≤ 2:1 com branco/preto próximo).
**WCAG**: 1.4.3 Contrast (AA) — texto abaixo de 12px exige 4.5:1
**Recomendação**: `text-[10px]` → `text-xs` (12px)
**Comando sugerido**: `impeccable typeset`

### [P2] Cores semânticas hard-coded fora do token system

**Localização**: `src/App.tsx` — `text-emerald-500`, `bg-emerald-500/20` (resultado aprovado); `src/index.css` — `.concept-*` classes com hex literais
**Categoria**: Theming
**Impacto**: Verde de "Aprovado" não é afetado pelo dark mode — `text-emerald-500` é Tailwind estático, não responde a `--primary` ou outros tokens de tema. No dark mode, o contraste do verde sobre `#011640` não foi verificado.
**Recomendação**: Adicionar token `--success` / `--success-foreground` no `:root` e `.dark`, e mapear as `.concept-*` classes para os tokens já existentes (`--primary`, `--accent`, `--destructive`).
**Comando sugerido**: `impeccable colorize`

### [P2] Dois sistemas de cor muted em paralelo

**Localização**: `src/index.css` define `--text-muted: #636e72` como CSS var; `text-muted-foreground` é o token Tailwind/shadcn que aponta para `--muted-foreground` do shadcn
**Categoria**: Theming
**Impacto**: Os elementos que usam `.technical-header` leem `var(--text-muted)`. Os elementos que usam `text-muted-foreground` leem o token shadcn. Em dark mode, `--text-muted` fica `#a4b0be` (definido em `.dark`), mas o token shadcn `--muted-foreground` tem seu próprio valor dark. Os dois podem divergir visualmente.
**Recomendação**: Escolher um sistema. Preferência: alinhar `--text-muted` ao valor de `--muted-foreground` do shadcn, ou apontar `.technical-header` para `text-muted-foreground` e remover `--text-muted`.
**Comando sugerido**: `impeccable extract`

### [P2] `opacity-60` residual no subtítulo do header

**Localização**: `src/App.tsx` linha ~235 — `<p className="text-sm font-medium opacity-60 uppercase tracking-[0.2em]">`
**Categoria**: Acessibilidade
**Impacto**: `text-sm` (14px) com `opacity-60` sobre `var(--text)` = `#011640` no fundo `#eef2f5`. A razão de contraste efetiva é ~3.2:1, abaixo de 4.5:1 exigido para texto normal. Estava fora do escopo da correção tipográfica anterior (que focou em `text-[9px]`/`text-[10px]`), mas viola o mesmo padrão.
**WCAG**: 1.4.3 Contrast (AA)
**Recomendação**: `opacity-60` → `text-muted-foreground` sem opacidade
**Comando sugerido**: `impeccable typeset`

### [P2] Sem `<main>` landmark na estrutura semântica

**Localização**: `src/App.tsx` — estrutura raiz `<div className="min-h-screen...">`
**Categoria**: Acessibilidade
**Impacto**: Screen readers anunciam regiões da página para navegação rápida (tecla `M` no NVDA). Sem `<main>`, o usuário Sam não pode saltar diretamente ao conteúdo principal.
**WCAG**: 1.3.6 Identify Purpose (AA); ARIA Landmark Regions (best practice)
**Recomendação**: Substituir o `<div>` raiz por `<main>` ou adicionar `role="main"`:
```tsx
<main className="min-h-screen p-4 md:p-8 max-w-4xl mx-auto transition-colors duration-300">
```
**Comando sugerido**: `impeccable audit`

**Localização**: `src/index.css` — `.dark { --primary: #D90404; }`

## Padrões Sistêmicos

**1. Token de cor incompleto para estados semânticos**: "Aprovado" usa `emerald`, erros usam `red-500`, avisos usam `amber-500` — todos Tailwind estático, fora do sistema de tokens. Um único passo de `impeccable colorize` pode mapear `--success`, `--warning` e garantir que o dark mode os adapte corretamente.

**2. Dois legados de muted color**: `var(--text-muted)` (CSS var) e `text-muted-foreground` (Tailwind shadcn token) coexistem e podem divergir. Escolher um e unificar elimina um vetor de inconsistência visual em futuras alterações.

## Achados Positivos

- **Focus indicators completos**: `nm-inset:focus-within`, `nm-btn:focus-visible`, `nm-btn-primary:focus-visible`, `InfoTooltip` com `focus-visible:outline`, resultado Card com `focus-visible:outline` — cobertura de foco muito boa para o estilo neumórfico.
- **Validação de campos bloqueante + avisos não-bloqueantes**: distinção entre erros (bloqueia cálculo) e warnings (informa mas permite calcular) é UX correto para contexto oficial.
- **`aria-label` em todos os botões de ícone**: dark mode toggle, reset, tabelas, imprimir — todos rotulados.
- **Print mode funcional**: `print:hidden` em formulário/header/footer + `@media print` com limpeza de sombras neumórficas — resultado de impressão é limpo.
- **Popover para InfoTooltip**: migração de hover-only para Radix Popover resolve touch e keyboard em uma única mudança.
